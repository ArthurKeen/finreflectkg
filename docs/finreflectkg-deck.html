01 The dataset

A dense, decade-long record of corporate self-disclosure.

FinReflectKG is distilled from the annual 10-K filings of the S&P 500 (research paper 2508.17906). Every fact is grounded in the sentence that produced it.

  • 17.5M relationship occurrences across 3.1M entities — 1.67 GB of raw parquet.
  • 1.38M source text chunks keep every edge traceable back to the filing.
  • Nine entity kinds: FIN_METRIC, ORG, GPE, RISK_FACTOR, PRODUCT, SEGMENT, FIN_INST, FIN_MARKET, PERSON.
The challenge

Metric-dominated & noisy. Financial metrics swamp centrality, OCR-era dates parse to absurd years, and anonymous mentions ("a supplier", "default") collapse into cross-company super-hubs. Turning this into a trustworthy graph was as much of the work as loading it.

02 Graph model — LPG

One node collection, one edge collection, entity resolution for free.

A Labeled Property Graph in Neo4j terms: identity is hash(name │ type), so the same concept mentioned in 743 filings resolves to a single node automatically.

Node3.1M · hash(name│type)
depends_on · operates_in · has_stake_in …
Node_fromType → _toType
Edges carry context

ticker, year, startDate/endDate, source chunk — and the endpoint types, so a typed hop needs no vertex lookup.

Supernode-safe

Two vertex-centric indexes turn typed 1-hops into direct edge queries. net income (in-degree ~10⁵) scans only its 59,315 matching edges — not the whole hub.

03 Sharding — three distributions, benchmarked

The same graph, placed three ways — because placement is the performance story.

ArangoDB lets the physical layout vary while the model stays fixed. We built and benchmarked three (goal G7).

Baseline

FinReflectKG

Flexible single-shard. The reference point for every comparison.

Recommended

OneShard

All collections co-located on one DBServer. ~4× faster on 2-hop traversals — it removes the cross-DBServer RemoteNode hops.

Locality play

SmartGraph

Per-company concept duplication → 6.66M nodes (2.1×), trading storage for company-local traversals.

Shared-cluster latency is noisy (203 ms–20 s for one query), so the deterministic metrics are scanned-edge counts and shard-locality from explain — not wall-clock.

04 Ask in English → Cypher → grounded answer

A natural-language front door, with citations back to the filing.

English question → Cypher (via the arango-cypher-py integration, a first-class Cypher surface over ArangoDB) → executed → GraphRAG synthesis that grounds the answer in the retrieved edges and their source 10-K text.

  • Every answer is traceable — edge provenance + chunk text, no free-floating claims.
  • Cypher, not a bespoke DSL: the query layer is portable and inspectable.
Honest evaluation
4 / 5

GraphRAG answer synthesis (gpt-4o). NL→Cypher: 19/22 transpile, 9/22 execute. LLM-dependent scores are provider-dependent and re-measured on provider change (§4.6).

05 Graph analytics — GAE

Whole-graph algorithms, and an agent that plans them.

Pregel is deprecated on 3.12, so analytics run on the Graph Analytics Engine — PageRank and connected components over all 17.5M edges.

Deterministic base

PageRank + WCC verified on the full graph — the influence and community backbone the rest of the analysis builds on.

Agentic planning

A pipeline turns a natural-language goal into an analysis plan, runs it on GAE, and writes a report — validated across 10 use cases.

The report stage is wired — the tool’s own generator renders Plotly HTML from stored GAE results (scripts/analytics_report.py). Remaining (optional, REQ-011): closing the loop into fully-autonomous NL → execute → report.

06 Time-travel — the headline capability

Ten years of filings means the graph can be rewound to any instant.

A valid-time interval model — adapted from our network-asset "TTL" blueprint, but as a permanent archive (no deletion). Validity lives directly on the existing edges; no overlay collection.

Encoding

validFrom/validTo as YYYYMM ints, exclusive end, NEVER_EXPIRES sentinel for open rows.

Queries

as-of vFrom≤t AND vTo>t · current vTo==NEVER · diff t₁→t₂ = two as-ofs + MINUS.

Index-backed

An MDI index makes direct as-of scans index-covered; node-anchored typed as-of uses a composite VCI. Verified via explain.

Built & validated in FinReflectKgTemporal (OneShard) — all 17.51M edges carry validity.

07 Bitemporal — two axes, no new fields

When a fact was asserted vs. when it was true.

The filing year is the transaction-time axis; validFrom/validTo is the valid-time axis. Together they make the graph bitemporal — enabling "as-known-as-of" queries and restatement detection.

  • 1.82M edges (10.5%) are backward-looking — a filing asserting a fact about a period years earlier.
  • Led by utilities and insurers, whose disclosures reach furthest back.
Why it matters

You can reconstruct not just what was true in 2018, but what the company said in 2018 about 2015 — the raw material for spotting restatements and revised guidance, with zero schema changes.

09 Data quality — the blank-node problem

"CINC depends on Supplier" is a blank node, not a fact.

Extraction collapsed anonymous mentions — a supplier, a default — into single cross-company super-hubs. This is exactly RDF's blank-node problem, and it was poisoning centrality.

◤ Raw — conflated hubs
supplierdistributorcompetitordefaultother

One "supplier" node wired to hundreds of unrelated companies — a phantom super-hub that outranked real concepts.

◥ Cleaned — skolemized
bn_aapl_supplierbn_cinc_supplierbn_msft_vendor

5,893 per-company blank nodes minted; 23 junk placeholders excluded (not skolemized). 89 hubs flagged in all.

Discriminator is role-lexicon × cross-company fan-in, not fan-in alone — so genuinely shared concepts (common stock: 716 companies, dividend, long-term debt) stay intact. PageRank was re-run on the cleaned snapshots.
